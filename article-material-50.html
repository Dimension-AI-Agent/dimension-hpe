RACI-O：AI Agent 導入後，企業如何重新定義權責？

AI Agent 進入企業流程後，傳統 RACI 不足以處理「誰能推翻 AI」的問題，因此 Deloitte 提出 RACI-O，新增 O（Override Authority）。 核心原則： - R、C 可以由人類或 AI Agent 擔任。 - A、I、O 仍由人類承擔，其中 A 負責最終成果，I 接收進度與結果資訊，O 保有覆核／推翻 AI 的權力。 RACI-O 的重點不是限制 AI，而是確保： > AI 可以執行與提供建議，但人類仍保有最終責任、知情權與最後決定權。

權責分工人工接手RACI-O

當 AI Agent 開始參與企業工作流程，傳統 RACI 已不足以完整描述人與 AI 的責任關係。

Deloitte 因此提出加入 O（Override Authority，覆核／推翻權），形成 RACI-O。

角色 定義 人類 AI Agent
R — Responsible 實際執行工作 ✓ ✓
A — Accountable 對最終成果負責 ✓ ✗
C — Consulted 提供資訊或專業意見 ✓ ✓
I — Informed 接收進度與結果資訊 ✓ ✗
O — Override 有權否決、修改或例外核准 AI Output ✓ ✗

核心原則是：

AI 可以執行工作，但最終責任與最後決定權仍應保留在人類手中。

為什麼需要 Override Authority？

當 Agent 開始能夠：

  • 做出 Recommendation
  • 呼叫 Tools
  • 修改資料
  • 執行交易
  • 自主完成 Workflow

企業就不能只定義「誰負責執行」，還必須回答：

如果 AI 的判斷不適合當下情境，誰有權阻止或修改它？

這就是 O 的作用。

Override Authority 應由明確指定的人類角色持有，並具備：

  • Approve
  • Reject
  • Modify
  • Escalate

等正式決策權。

因此 Human-in-the-loop 不應只是「有人看一下結果」，而是要清楚定義：

誰可以在必要時對 AI 說不。

Accountability 不能交給 AI

Agent 可以成為 Responsible，負責執行實際工作，但 Accountable 仍需由人類承擔。

例如 Invoice Review Agent 可以自動：

  • 讀取發票
  • 比對採購單
  • 找出異常
  • 建議 Approve / Reject

但主管仍需對：

  • 審查品質
  • 錯誤
  • Business Outcome
  • Agent 的持續改善

負責。

換句話說：

執行可以自動化，但 Accountability 不能被自動化。

A 與 O 不一定是同一個人

一般低風險流程中：

A + O = Department Manager

但在高風險或受到監管的流程中，可以拆開：

A = Business Owner
O = Risk / Legal / Compliance

如此可以把「業務成果責任」與「風險控制權」分開。

導入 Agent 時，可以直接用五個問題檢查

  1. R：誰實際執行工作？
  2. A：誰對結果負責？
  3. C：Agent 需要向誰或什麼取得資訊？
  4. I：誰需要知道執行結果？
  5. O：如果 Agent 判斷錯誤，誰可以阻止或推翻它？

RACI-O 的價值不在於限制 AI，而是在 Agent 自主性提高後，仍保留清楚的：

Accountability、Decision Rights、Human Oversight 與 Escalation Path。

AI Agent 可以是 Responsible，也可以是 Consulted；但 Accountable 與 Override Authority 應保留在人類手中。
