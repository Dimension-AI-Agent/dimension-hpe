企業 AI 與 Agent 實務 / 外部 AI 應用案例

Rakuten 如何運用 Claude Code 重整開發流程並縮短功能交付時間

Anthropic 發布的 Rakuten 客戶案例描述，工程團隊將 Claude Code 用於測試、API 模擬、元件開發、除錯與文件工作，並重新調整開發流程。案例自述新功能平均上市時間由 24 個工作日縮短至 5 日，約減少 79%。其行銷參考價值在於呈現工作方式改變與業務指標之間的關聯。數據屬供應商客戶故事，未提供足以獨立重算的完整資料，不能視為其他企業的預期成效或訊達的交付承諾。

本文整理外部公開案例，並非訊達客戶導入實績。原文與資料來源見文末。

外部案例Claude CodePilot流程設計商業效益

Rakuten 如何運用 Claude Code 加速軟體開發(已翻譯成中文)

產業： 電子商務
企業規模： 大型企業
使用產品： Claude Code
地區： 亞太地區

關鍵成果

Rakuten 導入 Claude Code 後，取得幾項具體成果：

  • 新功能從開發到上市的平均時間由 24 個工作天縮短至 5 天，減少 79%
  • Claude Code 曾針對複雜的開源專案重構工作，進行 連續 7 小時的自主程式開發
  • 在複雜程式碼修改任務中達到 99.9% 的數值準確率
  • Claude Managed Agents 在一週內部署至產品、業務、行銷與財務等不同部門

讓所有團隊更快速地進行創新

Rakuten 旗下擁有超過 70 個業務，涵蓋電子商務、旅遊、金融科技、數位內容與通訊等領域，因此公司希望利用 AI 同時改善客戶、合作夥伴與員工的工作體驗。

Rakuten AI for Business 總經理 Yusuke Kaji 認為，AI 的目的並不只是自動化既有工作，而是放大每個團隊可以完成的事情，讓不同部門可以更快速創新，並更快為客戶創造價值。

然而 Rakuten 擁有數千名開發人員，同時服務數百萬名客戶，因此導入 AI 時不能只考慮速度，也必須維持大型企業所需要的品質與資訊安全標準。

Rakuten 衡量 AI 成效時，特別關注兩個指標：

  • Speed：速度
  • ROI：投資報酬率

因此，他們並不是單純衡量 AI 能多快產生程式碼，而是觀察 AI 可以多快協助公司把真正的價值交付給客戶。

Rakuten 將這套全面導入 AI 的策略稱為 AI-nization。

除了使用外部 AI 工具，Rakuten 本身也開發 AI Agent、使用開源模型，甚至從底層建立大型語言模型。這些經驗讓公司對 AI 技術的能力與限制有更深入的理解。

當 Anthropic 推出 Claude Managed Agents 後，Rakuten 也將 Agent 部署至產品、業務、行銷與財務等部門。

這些 Agent 可以整合 Slack 與 Microsoft Teams。員工可以直接把任務交給 Agent，再取得試算表、簡報、應用程式等實際成果。

Rakuten 表示，一個專業用途的 Agent 最快可以在一週內完成部署。

這代表公司不必自行建立完整的 Agent 基礎設施，而可以把資源集中在如何讓更多員工實際使用 AI，以及如何把 AI 能力擴展至不同業務場景。

為什麼 Rakuten 選擇 Claude Code

Rakuten 在評估市場上的 AI 程式開發工具時，發現一個共同問題：

許多工具仍然需要工程師持續提供指示，而且面對大型、多程式語言、架構複雜的程式碼庫時，能力有限。

Claude Code 在這兩方面的表現讓 Rakuten 特別關注。

Rakuten 發現，Claude Code 可以在相對少的人為介入下完成長時間、複雜的軟體開發工作，因此 AI 不再只是工程師旁邊的輔助工具，而可以變成一個可以被指派工作的執行單位。

例如，一名工程師可以同時處理五項工作：

自己負責其中一項，另外四項分別交給不同的 Claude Code Session 執行。

這使 AI 開始具備放大工程團隊產能的效果。

七小時自主開發實驗

Rakuten 機器學習工程師 Kenta Naruse 曾經設計一項測試，用來確認 Claude Code 是否真的能處理大型、複雜的工程任務。

任務內容是：

在 vLLM 中實作一種特定的 activation vector extraction 方法。

vLLM 是一個大型開源專案，程式碼規模約 1,250 萬行，而且包含多種程式語言。

Claude Code 在一次執行中持續工作約 7 小時，最後完成整項任務。

在這七小時內，工程師本身幾乎沒有撰寫程式碼，只在必要時提供少量指導。

最終實作結果與參考方法相比，達到約 99.9% 的數值準確率。

這次實驗讓 Rakuten 進一步確認，AI Coding Agent 不只適合小型開發任務，也可能處理企業級、長時間而且技術難度較高的工程工作。

重新設計開發流程，而不是把 AI 塞進原本流程

Rakuten 並沒有單純把 AI 加進既有軟體開發流程，而是開始依照 Claude Code 的能力重新設計工作方式。

工程師目前會在整個軟體開發生命週期中使用 Claude Code，包括：

  • 撰寫 Unit Test
  • 建立 Mock API
  • 開發軟體元件
  • 修復 Bug
  • 產生技術文件
  • 理解既有程式碼
  • 理解系統架構與過去的技術決策

對剛加入團隊的新工程師而言，Claude Code 也能協助快速理解大型程式碼庫，降低熟悉既有系統所需的時間。

AI Code Review

其中一項應用是利用 AI 進行 Code Review。

當工程師提出 Pull Request 時，AI 可以立即提供程式碼相關的意見。

這同時改善：

  • Code Quality
  • Review Speed
  • Development Speed

因此 Code Review 不再完全依賴其他工程師排出時間人工檢查。

Parallel Development：平行開發

另一個重要變化是平行開發。

工程師可以同時啟動多個 Claude Code Session，分別執行不同工作。

傳統開發模式中，一名工程師通常一次只能專注處理少數工作；AI Agent 則讓工程師可以同時管理多條工作線。

這可以降低等待與工作切換造成的瓶頸。

AI 也改變工程師的開發方法

Rakuten Senior Machine Learning Engineer Diego Mateos 表示，Claude Code 甚至改變了他的程式開發習慣。

例如他過去並不會自然採用 Test-Driven Development（TDD）。

但 Claude Code 可以快速產生完整測試，再根據測試要求建立功能，因此讓 TDD 的執行成本大幅降低。

換句話說，AI 不只是提高原本開發流程的速度，也可能改變工程師實際採用的軟體工程方法。

可量化的商業成果

Rakuten 導入 Claude Code 後，其中最明顯的成果是 Time to Market。

新功能平均上市時間：

24 個工作天 → 5 個工作天

等於縮短約：

79%

Rakuten 認為，真正重要的不是 AI 產生多少程式碼，而是整個產品交付速度是否因此提升。

七小時自主開發實驗在公司內部也產生很大影響。

當其他團隊知道 Claude Code 在只有少量人工介入的情況下完成長時間複雜工程工作後，開始重新思考 AI 可以參與哪些工作。

讓非工程人員也能參與技術工作

Rakuten 也開始讓非工程背景員工使用 Claude Code。

雖然 Claude Code 採用 Terminal Interface，但使用者不一定需要直接修改程式碼。

只要提供：

  • 適當的 Context
  • Coding Guidelines
  • 任務需求

Claude Code 就可以代為執行部分技術工作。

因此，原本只有工程師能處理的一些任務，開始可以由其他角色參與。

同時，透過既定的開發規則與 Context，也可以建立一定程度的安全護欄。

Rakuten 認為，這種能力有助於提升整體組織的創新速度。

公司目前除了觀察一般軟體工程指標外，也開始追蹤：

  • Test Coverage
  • Innovation Velocity
  • AI-nization Ratio

等 AI 導入相關指標。

從單一 Agent 進一步發展成多 Agent

在成功案例之後，Rakuten 開始測試更複雜的 Agent 架構。

Kenta Naruse 正在建立一種稱為 Ambient Agent 的系統。

這個 Agent 可以先把一個大型任務拆解，再同時啟動：

24 個 Claude Code Session

每個 Session 分別負責大型 Monorepo 更新工作中的不同部分。

原本如果完全由工程師手動執行，類似工作可能需要超過一個月。

這種架構代表 AI Coding 的模式開始從：

人類 → 一個 AI Assistant

進一步發展成：

人類 → Agent Orchestrator → 多個平行工作的 Coding Agents

從 Pilot 擴大至企業規模

在初期 Pilot 成功之後，Rakuten 管理層決定進一步擴大 Claude Code 的使用範圍。

公司的方向是讓 Claude Code 從處理：

短時間、單一任務

逐漸發展至：

複雜、持續數小時的工作流程

並讓這類 AI 工作方式成為日常開發流程的一部分。

Rakuten 認為 Claude Code 並不只是單一工具，而是整個企業 AI 轉型過程的一部分。

Rakuten 的企業 AI 導入模式

Rakuten 的案例呈現出一種企業導入 AI Agent 的可能路徑：

1. 先選擇明確、可衡量的高價值 Use Case

例如軟體開發與 Time to Market。

↓

2. 透過實際 Pilot 驗證 Agent 能力

例如讓 Claude Code 處理 vLLM 的大型複雜工程任務。

↓

3. 用商業與工程指標評估效果

包括：

  • Time to Market
  • Test Coverage
  • AI-nization Ratio
  • Innovation Velocity

↓

4. 不只是自動化既有流程，而是重新設計流程

例如：

  • Parallel Development
  • AI Code Review
  • Agent-driven Development

↓

5. 將 AI 從工程部門擴展至其他部門

包含：

  • Product
  • Sales
  • Marketing
  • Finance

↓

6. 從單一 Agent 進一步發展至 Multi-Agent 架構

例如利用多個 Claude Code Session 平行執行大型任務。

↓

7. 最終讓 AI 成為企業日常營運與開發基礎設施的一部分

Rakuten 的核心思路並不是單純追求「AI 可以產生多少內容或程式碼」，而是觀察 AI 是否能實際縮短價值交付時間、提高組織產能，並讓更多員工具備原本受到專業能力限制的執行能力。
