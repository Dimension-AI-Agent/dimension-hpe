Agent 何時應停止並轉交人工

企業導入 AI Agent 前，需要先約定哪些情況必須停止自動執行並交由人員處理。常見觸發條件包括多次失敗仍無法完成任務，以及涉及高風險、不可逆或重大影響的操作。人工介入流程還應交付必要的處理紀錄，並明確定義核准、修改或拒絕後的下一步，讓人員能有效接手。

人工接手流程設計

AI Agent 何時應停止執行，並轉交人工處理？

AI Agent 可以連續執行多個步驟，但企業仍需要事先定義停止條件。當系統無法可靠地繼續，或下一步涉及重大影響時，應依規則暫停或終止自動處理，交由人員判斷。

人工介入需要安排在具體流程中：什麼情況觸發、由誰接手、需要看到哪些資訊，以及處理後能否繼續。

第一類：達到失敗門檻，仍無法完成任務

常見情況包括：

  • 多次詢問後，仍無法確認使用者意圖。
  • 重複呼叫工具，仍未取得必要資訊。
  • 連續產生不符合要求的結果。
  • 流程反覆回到相同步驟，沒有實質進展。

企業應依任務設定可接受的嘗試次數、處理時間或失敗條件。達到門檻後，Agent 應停止自行嘗試，交付目前結果與未解決問題。

不同錯誤也需要不同處理方式。例如暫時性連線問題可能適合有限重試；權限不足、資料衝突或無法理解需求，則可能需要人員確認。

第二類：即將執行高風險或重大影響的操作

是否需要人工確認，應看操作的影響、可逆性及所需權限，而不只看 Agent 對答案有多高信心。

評估面向 需要確認的問題
外部影響 是否會改動客戶資料、訂單狀態或其他系統紀錄？
財務影響 是否涉及退款、付款或其他金額承諾？
可逆性 執行後能否撤回？撤回需要付出什麼代價？
授權範圍 Agent 與核准人員是否具備所需權限？

例如，整理退款申請資料與執行大額退款，是不同風險的工作。企業可以允許 Agent 自動產生建議，但在實際退款前安排人員確認。

這些條件應由業務與系統負責人事先約定，並落實於流程及權限控制。

轉交時，讓人員知道發生了什麼

有效的人工介入需要足夠的資訊，讓接手者能判斷下一步。

轉交內容可以包含：

  • 使用者的需求與目前處理狀態。
  • 已取得的資料與判斷依據。
  • 已完成的步驟及尚未執行的操作。
  • 失敗原因、資訊衝突或其他不確定事項。
  • Agent 的建議，以及需要人員決定的問題。

如果即將執行外部操作，也應清楚呈現操作對象與預期影響，讓人員能審查實際內容。

明確定義核准、修改與拒絕後的下一步

人工審核可以有三種結果：

  • 核准：依核准範圍接續指定步驟。
  • 修改：使用確認後的內容重新檢查，再依流程處理。
  • 拒絕：停止該項操作，或交由人員改採其他方式。

等待核准期間，相關操作應維持暫停。重新執行時，也需要避免重複完成先前已做過的動作。

這些行為需要實際的流程與系統設計；單靠提示詞要求 Agent「記得等待核准」，不足以取代操作限制。

用失敗與拒絕情境測試人工介入

驗證時，除了測試人員核准後能否繼續，也應確認：

  • 達到失敗門檻後，Agent 是否真的停止。
  • 高風險操作是否在執行前觸發審核。
  • 人員未回覆時，相關操作是否保持暫停。
  • 人員拒絕後，Agent 是否仍嘗試執行。
  • 接手者是否能從紀錄理解狀況。

人工介入需要搭配身分驗證、授權、存取控制及其他防護措施。後續若要調整審核範圍，也應根據測試結果與實際風險決定。
